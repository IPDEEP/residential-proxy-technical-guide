# Contributing

Thank you for helping improve this technical guide.

## Good contributions

- Correcting a technical error with a reliable reference.
- Adding reproducible examples using placeholder credentials.
- Improving explanations, accessibility, and navigation.
- Adding diagnostic steps that are safe and authorized.

## Before submitting

1. Keep examples generic and reproducible.
2. Do not include real credentials, API keys, private endpoints, customer information, or personal IP addresses.
3. Cite authoritative technical references where appropriate.
4. Explain assumptions, supported versions, and limitations.
5. Do not add instructions for fraud, unauthorized access, evading platform safeguards, or concealing abusive activity.
6. Check spelling, Markdown links, and code formatting.

## Pull request description

Include the problem addressed, the files changed, how examples were tested, and any limitations readers should know.
