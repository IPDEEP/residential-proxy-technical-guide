# 08｜代理网络稳定性与连接故障诊断

代理连接失败不一定意味着 IP 地址本身存在问题。建议按照网络层次逐步排查。

## 1. 先确认基础参数

检查：

- 代理主机名或 IP；
- 端口；
- 协议类型；
- 用户名和密码；
- 账号状态及服务限制；
- 当前客户端是否支持该协议。

不要根据端口号猜测协议。

## 2. 检查主机和端口连通性

macOS / Linux：

```bash
nc -vz proxy.example.net 10000
```

Windows PowerShell：

```powershell
Test-NetConnection -ComputerName proxy.example.net -Port 10000
```

TCP 连接成功只说明主机和端口接受了连接，不代表代理认证、协议协商和目标访问都成功。

## 3. 检查延迟

可以通过多次、固定条件的请求观察延迟变化。测试时应记录目标地址、测试时间、网络环境和客户端版本。

单次 ping 结果不能代表代理应用的完整请求延迟；部分服务也可能不响应 ICMP。

## 4. 常见错误

| 现象 | 可能原因 | 建议检查 |
|---|---|---|
| 连接超时 | 路由、网络过滤、服务不可用或超时设置 | 主机、端口、网络和服务状态 |
| Connection refused | 端口未监听或端点错误 | 端口和服务配置 |
| HTTP 407 | 代理认证失败或缺少认证 | 用户名、密码、认证方式 |
| DNS 解析失败 | 本地或代理侧 DNS 问题 | 客户端 DNS 模式和解析器 |
| TLS 证书错误 | 证书链、系统时间或 TLS 配置问题 | 证书与客户端配置 |
| 目标站点 403 | 目标服务拒绝请求 | 目标站点策略和请求授权 |

## 5. 分层排查顺序

1. 代理主机名解析；
2. TCP 主机与端口连通；
3. 代理协议协商；
4. 代理认证；
5. 目标域名解析；
6. 目标服务器连接；
7. TLS 握手；
8. 应用层响应。

不同客户端能展示的诊断细节不同。

## 6. 提交技术支持时应提供什么？

可以提供操作系统、客户端及版本、协议类型、测试时间、脱敏错误信息和复现步骤。

不要提供明文密码、完整凭据 URL、API Key 或客户个人信息。
